# German grammar (A1–B2, C1 where reliable)

Contributor request (mrAlishah, PR #233), 2026-11-14; merged by the maintainer with the review fixes below.
In this spec "owner" and "user" mean the contributor who directed the work on their fork, not this
repository's maintainer, unless it says "maintainer".
Offline only: no network, no AI, no new permission. Optional AI explanations (Stage 6) are not part
of this work and stay disabled; the existing "Ask AI" button of the grammar section will appear for
German like for every language with a grammar section (it is user-started and unchanged).

## Release intent

The change reaches the APK (`app/src/main/**`, `app/build.gradle.kts`): **patch**, per the repo's
default. Not a skip. Confirm with the owner before handoff.

## Problem

German words are tagged with a Universal Dependencies part of speech (OpenNLP UD GSD model) and
coloured, but the word card says nothing else about German: no dictionary form, gender, plural,
case, tense, mood, and no grammar points. English, Japanese, Chinese and Spanish have them.

## Constraints (verified against the working tree)

- `grammarLanguage` / `grammarMatches` (`data/LearnerGrammar.kt`) is the only dispatch. Grammar is
  keyed by the tapped line's language code (`selection.wordLanguage`), not by subtitle slot, so
  German in the Original, Subtitle 1 or Subtitle 2 slot works with no slot change.
- `matchGrammar` gives each morpheme to one contiguous point, longest first. German frames are
  discontinuous (`habe … gelesen`, `stehe … auf`) and overlap (a Perfekt inside a `dass` clause).
- `GrammarMatch(form, start, end, meanings, level)` has two consumers: `grammarForSelection` and
  `GrammarExplanations.kt` (plus one androidTest constructor call).
- `GrammarMeaning` is the shared enum whose constants map to string resources per language
  (`GRAMMAR_MEANING_TEXT`); its constant name is the stable rule ID.
- The card already shows a point's first meaning and the others under "Show other meanings".
- Tests are plain JUnit4, no mocking. User text lives in `strings_<area>.xml` with every translated
  `values-*` folder (9 interface languages); `MissingTranslation` lint and `AppLanguageTest` fail on gaps.
- Must not change: `GermanMorphology.analyze`, `de-pos.zip` loading, `germanPartOfSpeech`, German POS
  colours, token offsets (`ENGLISH_TOKEN`), the null-while-loading fallback.

## Design

### 1. Morphology and lexicon

`GermanMorphology` keeps its API and gains `morphemes(line): List<Morpheme>?` (null while the POS
model or lexicon loads, like Spanish). Each `Morpheme` is German-case-preserving (never lowercased,
since capitalisation marks nouns) and carries, in the existing fields:

- `pos`: UD tag from the OpenNLP model.
- `baseForm`: lemma, only when the lexicon or a rule supports it; `*` otherwise.
- `conjugationForm` and `detail`: the readings joined by `|`, as Spanish does, using German codes
  (tense/mood: `PRES PRET PERF.PART INF PART1 IMP SUBJ1 SUBJ2 ...`; for nominals
  `case.gender.number` such as `NOM.M.SG`). All readings stay; none is dropped to look decisive.

New files (names are suggestions):

| File | Role |
| --- | --- |
| `data/GermanLexicon.kt` | loads `de-words.txt` / `de-verbs.txt`; `lemma`, `gender`, `plural`, `genitive`, verb principal parts, separable prefix, auxiliary |
| `data/GermanConjugation.kt` | regular conjugation rules plus irregular overrides; reverse lookup of a surface form to readings |
| `data/GermanMorphology.kt` (extended) | pieces → `Morpheme`s; reading ranking in context |
| `data/GermanGrammar.kt`, `GermanGrammarCatalogue.kt` | rules and contiguous catalogue |
| `ui/GermanGrammarText.kt`, `ui/GermanNounForm.kt`, `ui/GermanVerbForm.kt` | card text; noun and verb details like `SpanishVerbForm` |

Data files (`app/src/main/learner-data/`): `de-verbs.txt` and `de-words.txt`, **only what rules cannot
derive**: per lemma its gender, plural, genitive singular (n-declension flagged), verb principal
parts (3rd person present with stem change, Präteritum, Partizip II, Konjunktiv II when irregular),
separable prefix, auxiliary (`sein`/`haben`), and irregular comparative forms. Regular forms are
generated by rules; irregular surface forms are listed `=form tag lemma` as in Spanish. Closed
classes (articles, pronouns, prepositions with the case they take, modals, `sein`/`haben`/`werden`,
conjunctions) are hand-written code with tests, not data.

Ambiguity policy: `der` is NOM.M.SG, DAT.F.SG, GEN.F.SG, GEN.PL, or the relative/demonstrative
pronoun. The analyzer keeps every reading, ranks only on sentence evidence (the noun it precedes,
a governing preposition or verb), and the card shows at most three. No gender is inferred from an
article alone. No percentages anywhere.

Compounds: only when both parts are lexicon words and the split is unique; otherwise `baseForm`
stays `*`. Unknown words never get a lemma.

### 2. Rule taxonomy and IDs

A rule's ID is its `GrammarMeaning` constant, prefixed `DE_`; its form string (the card's headline)
is German, e.g. `haben/sein + Partizip II`. Groups:

| Group | Examples |
| --- | --- |
| Tense and mood | Präsens, Präteritum, Perfekt, Plusquamperfekt, Futur I/II, Imperativ, Konjunktiv I/II, `würde` + Infinitiv |
| Verb constructions | modal + Infinitiv, Ersatzinfinitiv, separable verb, reflexive verb, `zu`-Infinitiv, `um … zu`, `ohne … zu`, lassen/sehen/hören + Infinitiv, Partizip I/II as attribute |
| Voice | Vorgangspassiv, Zustandspassiv (marked ambiguous with the perfect of `sein`), Passiv with modal |
| Case and government | Wechselpräpositionen (Akk direction / Dat place), prepositions with fixed case, genitive prepositions, verb + preposition (`warten auf` + Akk), dative verbs, adjective + preposition |
| Sentence structure | verb-second, verb-final subordinate clause, relative clause, indirect question, Konjunktion groups (und/aber/oder/denn/sondern; weil/dass/ob/wenn/als/obwohl/damit/bevor/nachdem…), conditional, negation (`nicht`/`kein`/`nie`), question and imperative order |
| Noun phrase | article and adjective ending after definite/indefinite/zero article, n-declension, plural patterns, nominalisation, genitive attribute |
| Reported speech | Konjunktiv I, Konjunktiv II substitute |

Catalogue size is whatever passes precision gates; target about 80–120 points, A1–B2 complete,
C1 only where detectable. Each rule needs: ID, form, CEFR level with a rationale line in this spec's
table (below), one example sentence, positive tests, near-miss tests, and a stated ambiguity case.

CEFR placement: the scale is the Council of Europe CEFR (and its 2020 Companion Volume). There is
no free item-level grammar list for German: Profile deutsch and the Goethe-Institut exam
specifications are copyrighted, so they are used only as a reference for what is taught when, never
copied. Each level is therefore the author's placement, recorded with a one-line rationale per rule
and **not reviewed by a German teacher**. The rationale table is filled in as rules land (Stage 3).

### 3. Non-contiguous and overlapping points

Backward-compatible additions to `GrammarMatch` (defaults keep every existing call valid):

```kotlin
data class GrammarMatch(
    val form: String, val start: Int, val end: Int,
    val meanings: List<GrammarMeaning>,
    val level: GrammarLevel = JlptLevel.N5,
    val evidence: List<IntRange> = emptyList(),   // char ranges of the words that make up the point
    val tentative: Boolean = false,               // heuristic, not a reliable detection
)
```

- `start..end` stays the complete coverage (first to last evidence word), so existing consumers
  read the same values. `evidence` lists only the words that constitute the point; empty means the
  whole `start..end` (every other language).
- `grammarForSelection`: when a match has evidence, a selection belongs to it only if it overlaps an
  evidence range (a tapped word between `habe` and `gelesen` does not get the Perfekt card). The
  "starts right after the selection" particle rule applies only to matches without evidence.
- `matchGrammar` is untouched. `germanGrammar` runs the German rules over all indices **without**
  the exclusive-ownership filter, so points may overlap, then orders them by `start`, longest first.
  It reuses `GrammarRule`, `RuleHit`-style hits (extended internally with evidence) and the
  contiguous catalogue, so there is one architecture.
- Card UI: `tentative` shows a small "Likely" label on the point; reliable points show none.
  Ambiguity within one point is its `meanings` list (first = best supported, up to 3).
- Compatibility proof: unit tests assert English, Japanese, Chinese and Spanish matches and
  `grammarForSelection` results are identical before and after (golden outputs captured on this
  branch's base for their existing test sentences).

### 4. Compatibility with existing languages and features

`GrammarLanguage` gains `GERMAN`, dispatched for `de`, `de-*`, `de_*` (including `de-AT`, `de-CH`);
checked after Japanese so kana text is unaffected. `GRAMMAR_MEANING_TEXT` gains `GERMAN_GRAMMAR_TEXT`.
No change to: slot settings, ordering, RTL, translation pipelines, ChatGPT Subscription, Practice,
Vocabulary, Anki (inspected only; no exports, note types or storage). The analyzer runs off the UI
thread (`BackgroundLoaded`); composables only read results, as for Spanish.

### 6. Localization

Strings go in `strings_grammar_de.xml` (default English) and the same file in all 8 translated
`values-*` folders (vi, es, pt-BR, ja, ko, zh-CN, id, az), keyed `german_grammar_*`. German grammar
terms (Akkusativ, Konjunktiv II, Partizip II…) are kept in German in every language, with a short
explanation in the interface language. Non-English files are machine-drafted by the assistant and
**unreviewed**; they are listed in the spec's results with the date. Placeholders, XML escaping and
resource references are checked by the existing lint and `AppLanguageTest`.

### 7. Test corpus and accuracy criteria

- Unit tests per rule: positive, near-miss, false-positive risk, ambiguity, and (where relevant) a
  discontinuous case; plus the 20 acceptance sentences from the request, with assertions on
  reading sets, not just single labels.
- Robustness: umlauts, `ß`, capitalisation, punctuation, hyphenated compounds, `de-DE/AT/CH`,
  empty and malformed input, lexicon missing (analyzer returns null, UI shows nothing).
- Evaluation corpus `app/src/test/resources/de-grammar-eval.tsv`: about 150 sentences written by
  the author with expected rule IDs and evidence spans, kept separate from the unit-test examples.
  A test computes precision and recall per rule and overall and prints them. Targets, stated in
  advance: overall precision at least 0.90 and no shipped rule below 0.80 precision on the corpus;
  recall is reported, not gated. A rule that misses the precision target is removed or marked
  `tentative`, never loosened silently. The corpus is small and written by the implementer, so it
  measures regressions, **not** general German accuracy; the report says so.

## Implementation record (2026-11-14)

### What was built

- **Data** (`tools/german/build_german_data.py`, CC BY-SA 4.0 output, inputs' SHA-256 in each header): `de-verbs.txt` (3,831 verbs,
  92 KB) and `de-words.txt` (9,000 nouns and 2,089 adjectives, 232 KB). Verbs store only the principal parts the weak rules cannot derive;
  nouns store gender, every attested genitive and plural; adjectives only irregular comparatives.
- **Morphology** (`GermanConjugation.kt`, `GermanLexicon.kt`): conjugation of every cell (Präsens, Präteritum, Konjunktiv I and II,
  Imperativ, Partizip I and II, Infinitiv, separable forms attached and detached), reverse analysis that keeps every reading, noun forms
  with their possible cases, adjective degrees.
- **Sentence model** (`GermanSentence.kt`, `GermanFunctionWords.kt`): tokens as the tagger cuts them, clauses, and noun phrases whose
  features are the intersection of the noun's, the determiner's and the adjective endings' possible case, gender and number. `der` is
  therefore resolved by its noun phrase, never fixed to nominative masculine.
- **Rules** (`GermanGrammar.kt`): 55 points (`GrammarMeaning.DE_*`), A1 to B2, with evidence words and a `tentative` flag.
- **UI**: text for all points in 9 languages (`strings_grammar_de.xml`, `GermanGrammarText.kt`), `GermanWordForm` on the word card
  (dictionary form, verb cell readings, auxiliary, separable prefix, reflexive, modal; noun gender, plural, genitive; adjective degree;
  case, number and gender in the noun phrase, up to three), a "Likely" label for tentative points.
- **Compatibility**: `GrammarMatch` gained `evidence` and `tentative` with defaults; `grammarForSelection` gives an evidence point only to
  its words. Other languages' behaviour is unchanged (full unit suite green, see Validation).

### Deviations from the design above

- No `GermanGrammarCatalogue.kt`: no German point is a contiguous pattern that `matchGrammar` handles better than the rules do, so all
  points are rules. `matchGrammar` is untouched, as decided.
- `GermanNounForm.kt` and `GermanVerbForm.kt` are one `GermanWordForm.kt`.
- `AnalyzedToken` and `GermanMorphology.analyze` are unchanged: no lemma is added there, because Vocabulary and the dictionary may key
  on `baseForm`. Lemmas reach the card through `GermanMorphology.wordDetails`.
- The lexicon is loaded by its own `BackgroundLoaded`, apart from the POS model, so a lexicon failure can never remove POS colouring.

### Measured results (JVM, not a phone)

- **Morphology against Wiktionary's own tables** (a sample of 160 verbs and 220 nouns taken from the lexicon, so it measures the rules, not
  German): verb forms 2,940 of 2,949 (99.7%), noun forms 1,040 of 1,088 (95.6%). Misses: adjective-declined nouns (der Letzte), a few
  alternative spellings.
- **Development corpus** (`de-grammar-eval.tsv`, 93 sentences): precision 1.000, recall 1.000. **This is not an accuracy estimate**: the
  engine was fixed against its failures. It is gated (overall precision 0.90, per rule 0.80) as a regression check.
- **Held-out corpus** (`de-grammar-heldout.tsv`, 50 sentences written after the engine was finished and annotated before it was run):
  63 correct points, 1 false, 4 missed: precision 0.984, recall 0.940. Not gated. One author wrote the rules and the annotations and the
  sample is small, so treat it as an optimistic estimate with wide uncertainty. One data-coverage fix (nouns without a gender tag on their
  senses, such as Lehrer) was made after the first held-out run; the figures above are after it (before it: precision 0.984, recall 0.925).
- **Performance** (test JVM): lexicon load 52 to 258 ms (varies with JIT warm-up; budget 300), heap 11 MB (budget 15), analysis of a
  17-word line 0.7 to 1.5 ms median (budget 20). The first attempt missed the budgets (375 ms, 49 MB) because all paradigms were built at
  load; fixed by building only the stems that need an index.
- **Size**: data files 92 KB + 232 KB raw (budget 1.2 MB). APK difference was not measured.

### Hardening cycle (second pass)

**Linguistic fixes** (general rules, no sentence is special-cased; each has positive, negative, ambiguous and regression tests in `GermanGrammarTest`):

1. *Separable verbs such as `fernsehen`*: the closed list of real separable prefixes now follows the standard inventory (fern, heraus, hinunter, … about 70).
2. *Capitalised imperatives* (`Mach das Fenster zu!`) and 3. *lowercase separable imperatives* (`… ruf mich an`): the tagger gave these words noun, preposition and conjunction tags.
   A closed-class or noun tag on a word that is not a member of the known function-word inventory is now treated as a guess; a lowercase "noun" is a
   mis-tag because German nouns are capitalised; a capitalised sentence opener with an imperative reading followed by an article or object pronoun is a verb. Lines with no capital
   letter are not re-read. An imperative may now also be a separable verb (both cards).
4. *Adjective government* (`stolz auf meinen Sohn`): new points `DE_ADJEKTIV_PREP_AKKUSATIV` / `_DATIV` from a table of 36 adjective and preposition pairs, texts in 9 languages
   (`tools/german/build_german_strings.py` now lives in the repo), and a preposition directly after a predicate adjective is never read as a Wechselpräposition.

### Hardening cycle (third pass): accuracy review

Fixes, each a general rule with dev and regression tests (none of the test sentences is in a held-out set, apart from one disclosed below): a participle with an intensifier or a governed preposition is an adjective, not a Zustandspassiv;
`leider` and `nächst-` get no comparison card; an intensifier may stand inside a noun phrase; a capitalised adjective that opens a sentence before a noun is an adjective; a predicate adjective is never matched as a verb + preposition;
a participle of the perfect gets no Präsens card of its own. A morphology defect found on the way: reverse analysis could not read stem + `-n` forms (`hätten`, `würden`, `schrien`) or present participles. A new test checks reverse
analysis over Wiktionary's golden forms: **94.0% before, 99.6% after** (2,938 of 2,949).

**Which accuracy numbers are valid.** Held-out v2 and v3 were never edited (their SHA-256 values are enforced by tests).

### FrequencyWords provenance assessment (the frequency source is kept; accepted by the maintainer, same as the Spanish data)

1. **Licence of FrequencyWords:** "MIT License for code. CC-by-sa-4.0 for content." (repository README).
2. **Underlying source:** the 2018 lists come from the OpenSubtitles2018 corpus at OPUS. That page states no licence, copyright notice or terms of use; it asks for a link to opensubtitles.org and a citation of Lison and Tiedemann (LREC 2016).

4. **Subtitle sentences redistributed:** no.
5. **Frequency redistributed:** the counts are not, but the files list lemmas most common first, so the **rank order** of the selected lemmas is visible in the line order. The ranking, not the counts, is therefore partly present.

### Known limitations (the engine says nothing rather than guessing)

- Not implemented: participial constructions, nominalisation, general verb-second position, adjective and noun + preposition government,
  Konjunktiv I in the passive, `lassen`/`sehen`/`hören` + infinitive, compounds.
- Remaining defects (after the third pass): a participial adjective with no distinguishing signal (`ist verheiratet`, `sind begeistert`) still gets a tentative Zustandspassiv card, because
  participles such as `geschlossen` are genuinely both; a participle the lexicon does not know (`ausverkauft`) gets no card; an adjective phrase after a contracted article (`im nächsten Jahr`) gets no
  adjective-ending card; inversion is found only after a one-word first element (`Heute gehe ich`, not `Heute Abend gehe ich`); `Setz dich … hin` is flagged reflexive (arguably correct); a verb with a fixed
  preposition is also matched on its participle (`auf den Brief gewartet`, arguably correct). Fixed in the third pass: `leider`, intensifiers in noun phrases, capitalised adjective openers, `nächst-`,
  plural Konjunktiv II forms (`hätten`).
- Lemmas and noun phrases exist only for the 9,000 most frequent nouns and 3,800 verbs; other words get no details, never a guessed one.
- Adjective-declined nouns (der Letzte, der Vorgesetzte) are not recognised.
- Zustandspassiv versus predicate adjective is reported as tentative, not decided.
- Non-English texts are machine-drafted and unreviewed; CEFR placements are unreviewed.

## Phase 2: word explanations and verb conjugation (2026-11-15)

**Root cause.** The word card explained a word only when a Grammar Catalogue point matched it, so an adjective, adverb, pronoun, determiner, preposition or conjunction with no matching point got nothing.

**What was built.**
- `data/GermanWordRole.kt`: `germanWordRole(sentence, start, end)` gives the word's own job in its line (adjective degree and ending, adverb kind and word order, pronoun person, number, case and referent, articles, preposition government, conjunction verb position). It is independent of the catalogue. A role is `tentative` and keeps several cases when the line leaves it open (`sie`, `ihr`, `uns`); a word with no safe reading gets no role.
- `data/GermanConjugationTable.kt`: Präsens, Präteritum, Perfekt and Plusquamperfekt for six persons, built from stored principal parts and the lexicon's auxiliaries (haben, sein, both). A table that cannot be derived is omitted, not guessed. A participle links to its lemma, and the selected word's actual tense and row are marked.
- UI (`ui/GermanWordRoleCard.kt`, `GermanWordForm.kt`): header, dictionary form, properties, "Grammar in this sentence", a collapsed "Conjugation" section with tense chips, then grammar points. The open state is a new persisted key (`WORD_CARD_GERMAN_CONJUGATION_OPEN_PREFERENCE`, registered in `SETTING_SPECS`). Each conjugation row is one merged accessibility node.
- Strings: `strings_german_role.xml` in all nine locales. German terms stay German; the non-English texts are machine-drafted and not reviewed by a German teacher.
- No new AI request; Ask AI and the other languages are untouched; FrequencyWords is unchanged.

**Validation (2026-11-15).** formatCheck, complexityCheck, lintDebug, assembleDebug and assembleDebugAndroidTest pass. testDebugUnitTest: 1780 tests, 0 failures (26 new: `GermanWordRoleTest` 16, `GermanConjugationTableTest` 10). Emulator (pixel2Api36, API 36): 38 tests, 0 failures, including the 11 new `GermanRoleUiTest` tests (adjective, adverb, pronoun, no-catalogue word, ambiguous pronoun, closed-then-open conjugation with four tenses and six rows, past tabs, participle link, Light theme, translated slot, 280 dp width) and the existing German, word-learning and grammar UI classes.

**Not verified or known limits.**
- Nothing was checked on a physical phone or with a live video.
- No UI test for "models still loading" (`GermanMorphology` is a singleton); only the existing null-safe behaviour covers it.
- Relative-pronoun and demonstrative detection is heuristic; adverb lists are finite; the dative reflexive is not guessed; a verb with no listed auxiliary has no perfect tables.
- The role tests were written against this phase's own examples; they are not an independent accuracy estimate.
- Python tests: **NOT RUN, reserved for manual execution by the user.**
